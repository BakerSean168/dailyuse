# 设置模块说明

## 1. 功能定位

设置模块用于管理用户偏好配置。它围绕外观、语言、AI、隐私、快捷键、通知、实验功能、用户文件路径和高级设置形成闭环，是用户个性化体验的配置中心。设置持久化、偏好同步和启动时 bootstrap 在本模块中实现。

## 2. 当前功能说明

- 外观设置：主题模式（亮色/暗色/跟随系统）。
- 语言设置：语言、时区、日期格式、时间格式、周起始日、货币。
- AI 设置：AI 相关偏好配置。
- 隐私设置：个人资料可见性、在线状态、搜索控制、使用数据分享。
- 快捷键设置：键盘快捷键展示和编辑（当前只读展示）。
- 通知设置：通知渠道偏好。
- 实验功能：实验性功能开关。
- 用户文件路径：用户文件存储设置。
- 高级操作：设置导出/导入（JSON）、备份列表、同步状态。
- 设置持久化：所有设置存储为 JSONB，通过 Zod schema 验证。
- 偏好同步：设置变更后自动同步到前端展示层（主题、语言）。
- 启动时 bootstrap：登录后自动加载用户设置，登出时重置。

## 3. 用户路径

- 设置查看路径：用户进入设置页面，通过 Tab 切换不同设置分区，查看和修改配置。
- 主题切换路径：用户在外观设置中选择主题模式，系统立即应用主题变更并同步到 Desktop 窗口。
- 语言切换路径：用户在语言设置中选择语言，系统更新 vue-i18n 和页面 lang 属性。
- 设置导出路径：用户在高级操作中导出设置为 JSON 文件，可用于备份或迁移到其他设备。
- 设置导入路径：用户导入 JSON 文件，支持合并模式（patch）或覆盖模式（reset + import）。

## 4. 业务规则

- UserSetting 是设置模块核心聚合，所有偏好存储为单个 JSONB `preferences` 列。
- 偏好通过 Zod schema 验证，分为 10 个 category：appearance、locale、ai、privacy、notification、editor、shortcuts、experimental、ui、workflow。
- 每个 category 有独立的 Zod schema，支持 `.default()` 默认值。
- 设置变更为 patch 语义：只更新指定 category，不影响其他 category。
- 设置导出格式为版本化 JSON（version: '2.0.0'），支持跨设备迁移。
- PresentationPreferenceStore 是轻量级 store，用于 app bootstrap 阶段的主题和语言同步，在 API 加载前就生效。
- 客户端通过 HTTP 或 IPC 适配器访问设置能力，服务端通过模块组合根装配用例和仓储实现。

## 6. 当前问题

- 设置项生效时机和持久化路径需要在优化前确认：某些设置（如主题）立即生效，其他（如隐私）可能需要延迟生效。
- 平台差异设置：桌面路径、快捷键、通知权限在不同平台上的行为不同。
- 设置与其他模块运行时配置的边界：通知设置与 Notification 模块的偏好之间的关系。
- 快捷键设置当前只读展示，编辑能力尚未实现。
- 实验功能的管理策略不明确。

## 7. 优化机会

- 完成快捷键编辑能力。
- 为实验功能提供更好的管理和说明。
- 强化设置搜索能力，让用户快速找到特定设置项。
- 考虑设置的分组和层级展示优化。
- 为设置变更提供更好的撤销/重做能力。

## 8. 风险点

- 设置项生效时机：主题和语言立即生效，但某些设置可能需要重启。
- 平台差异：Desktop 和 Web 的设置项可能不同。
- 设置与其他模块的运行时配置边界。
- JSONB 存储的查询性能和索引策略。
- 设置导入的版本兼容性。

## 9. 后续待确认

- 快捷键编辑的实现方案。
- 实验功能的管理和说明策略。
- 设置搜索的实现优先级。
- 设置与其他模块偏好的统一策略。
- 设置的版本迁移策略（当 schema 变更时）。
