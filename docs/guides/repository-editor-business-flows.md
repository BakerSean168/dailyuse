# Repository 与 Editor 业务功能表单

## 1. 产品定位

本模块当前采用“统一资源库 + Markdown 优先编辑”的业务设计：

- Markdown 笔记是主要创作对象
- 图片、音频、视频、文档等资源作为仓库内可复用素材存在
- 所有资源都可以逐步支持 tags 与搜索，后续可演进为完整资源库
- 用户主视图采用固定资源分组，不强调用户自定义文件夹

当前推荐的产品规则：

- 默认展示固定分类：`notes`、`images`、`videos`、`audio`、`documents`、`other`
- 主用户路径不开放“创建文件夹”能力
- 用户只能新建笔记、导入资源、引用资源、搜索资源、收藏资源
- 文件夹能力保留在领域层作为兼容能力，但不作为当前产品主流程暴露

## 2. 核心业务约束

| 约束项       | 规则                   | 说明                                             |
| ------------ | ---------------------- | ------------------------------------------------ |
| 资源组织方式 | 固定类型分组           | 用户看见的是固定资源类型分区，而不是自由树形目录 |
| 用户创建能力 | 仅允许创建笔记         | 不向用户开放新建文件夹                           |
| 资源导入方式 | 统一走导入             | 图片、音视频、PDF、Markdown 都通过导入进入仓库   |
| 主要编辑对象 | Markdown               | 只有 Markdown 进入编辑器主流程                   |
| 媒体查看方式 | Viewer 模式            | 图片/视频/音频走预览器而不是文本编辑             |
| 资源引用方式 | Markdown 内引用        | 图片/附件通过 Markdown 链接语法引用              |
| 分享能力     | 支持路径引用与内嵌导出 | 默认保存路径引用，分享时可导出为自包含内容       |

## 5. 必备且优雅的补充功能需求

下面这些需求不是炫技型功能，而是让 Repository + Editor 真正顺手、闭环的必备能力。

### 5.1 资源插入器

建议增加统一的“插入资源”面板，支持：

- 插入已有图片
- 插入已有音视频
- 插入已有文档链接
- 插入已有笔记链接

优点：

- 避免图片插入、文件插入、笔记插入三套分裂流程
- 后续可扩展为 Slash Command 的底层能力

### 5.2 粘贴资源策略配置

建议支持针对图片粘贴的用户偏好：

- 默认上传并路径引用
- 默认转 base64 内嵌
- 粘贴时询问

优点：

- 满足“长期仓库编辑”和“即时分享写作”两类场景

### 5.3 资源失效检测

建议编辑器对 Markdown 中的图片/附件引用做失效检测：

- 路径存在则正常显示
- 路径失效则显示 broken 状态
- 可一键重新绑定到仓库中的其他资源

优点：

- 这是资源库产品中非常关键的“长期可维护性”能力

### 5.4 资源引用反查

建议对图片等附件增加“被哪些笔记引用”的反查能力：

- 资源详情页显示引用它的笔记列表
- 删除资源前先提示影响范围

优点：

- 防止删除图片后大量笔记失效
- 让资源真正成为仓库中的可管理资产

### 5.5 智能资源命名

建议上传或粘贴图片时自动生成更稳定的文件名：

- 基于当前笔记标题
- 加入日期时间
- 冲突时追加序号

示例：

- `meeting-notes-2026-03-11-01.png`
- `project-plan-2026-03-11-02.png`

优点：

- 比 `image-1.png` 更适合作为长期资源库

### 5.6 轻量资源属性面板

建议对资源补一个轻量属性面板：

- 路径
- 大小
- 类型
- tags
- 引用次数
- 创建时间

优点：

- 为未来扩展为“资源库”预留自然入口

### 5.7 最近插入资源

建议在插入资源时优先显示最近上传/最近插入的资源。

优点：

- 用户贴图时经常会连续插多张图
- 能显著降低查找成本

## 6. 推荐的产品优先级

### P0

- 收口“不允许用户创建文件夹”的主路径规则
- 编辑器支持粘贴图片自动上传并插入引用
- 编辑器支持从已有资源中插入图片

### P1

- 资源插入器统一面板
- 图片路径引用 / base64 内嵌模式切换
- 自包含分享导出

### P2

- 资源失效检测
- 资源引用反查
- 最近插入资源
- 轻量属性面板

## 7. 产品决策建议

推荐采用以下默认策略：

- 日常编辑默认使用“路径引用”
- 分享时提供“导出为自包含 Markdown”
- 固定类型分组视图作为主导航，不对普通用户暴露文件夹创建
- 所有资源长期保留 tags 能力，为未来资源库演进做准备

这套策略的优点是：

- 当前实现成本低
- 用户心智简单
- 后续仍能平滑扩展成更完整的资源知识库
