### 1. 为什么领域服务不是“纯函数”？

在 DDD 中，**纯函数**（输入 A -> 输出 B，不改变任何东西）最适合放在 **值对象 (Value Object)** 或 **工具类** 中。

**领域服务 (Domain Service)** 的出现是因为有些业务逻辑**无法归属于单个聚合根**。

#### 举个经典例子：转账 (Transfer)

- **场景**：从账户 A 转账 100 元给账户 B。
- **分析**：
	- `AccountA.withdraw(100)`：这是 A 的职责。
	- `AccountB.deposit(100)`：这是 B 的职责。
	- **谁来协调这一动作？** 你不能把 `AccountB` 传给 `AccountA`（聚合根之间尽量不直接持有引用）。

这时就需要一个 **领域服务**：

```TypeScript
// libs/domain-server/src/modules/finance/services/transfer.service.ts

export class TransferService {
  // 注意：这里注入的是 Repository 的【接口】，不是实现！
  constructor(
    private accountRepo: AccountRepository, 
    private exchangeRateService: ExchangeRateService // 可能还需要查汇率
  ) {}

  async transfer(fromId: AccountId, toId: AccountId, amount: Money): Promise<void> {
    // 1. 获取聚合根 (这不是纯函数，因为依赖了外部数据)
    const fromAccount = await this.accountRepo.findById(fromId);
    const toAccount = await this.accountRepo.findById(toId);

    // 2. 执行业务逻辑 (改变了内存中对象的状态)
    fromAccount.withdraw(amount);
    toAccount.deposit(amount);

    // 3. 甚至可能包含一些校验逻辑，比如跨行转账限额
    if (fromAccount.bank !== toAccount.bank) {
        // ...
    }
    
    // 4. 持久化 (通常领域服务可以调用 save，也可以由上层 Application Service 统一 save)
    // 在这里调用 save 意味着它产生了副作用，所以它不是纯函数
    await this.accountRepo.save(fromAccount);
    await this.accountRepo.save(toAccount);
  }
}
```

**结论**：

- 它依赖了 `Repository` 接口（外部状态）。
- 它改变了 `Account` 的状态（副作用）。
- 所以它**不是纯函数**。

### 2. 领域服务 vs 数据库持久化

你说“不包含数据库持久化逻辑”，这句话是对的，但需要精确定义：

- ✅ **Domain Service 包含**：对 Repository **接口** 的调用（如 `repo.findById`, `repo.save`）。它只知道“我要保存这个对象”，不知道“怎么保存”。
- ❌ **Domain Service 不包含**：SQL 语句、Prisma Client、TypeORM Entity、数据库事务开启/提交代码。

**分层图解：**

1. **Domain Service** (在 `domain-server`)：调用 `IUserRepository.save(user)`。
2. **Infrastructure** (在 `infrastructure`)：实现 `PrismaUserRepository.save(user)`，里面写 `prisma.user.create(...)`。

### 3. 三种逻辑的归属地（开发规范）

为了让你的代码清晰，请遵循以下分类：

|**逻辑类型**|**描述**|**归属地**|**例子**|**纯函数？**|
|---|---|---|---|---|
|**纯计算逻辑**|不依赖外部，输入固定输出固定|**Value Object** / **Domain Entity**|`Password.hash()`, `Money.add()`, `Email.isValid()`|✅ 是|
|**单聚合业务**|只涉及一个聚合根的状态变更|**Domain Entity (Aggregate Root)**|`User.changePassword()`, `Order.pay()`|❌ 否 (有状态变更)|
|**跨聚合业务**|涉及多个聚合根，或需要查库校验|**Domain Service**|`TransferService.transfer()`, `UserService.registerUnique()`|❌ 否|
|**流程编排**|负责 API 接入、事务管理、发邮件|**Application Service (Use Case)**|`RegisterUserUseCase`, `LoginController`|❌ 否|

### 4. 你的 Authentication 模块案例

回到你的 Auth 模块，如果你要写一个 **“检查邮箱是否唯一并注册”** 的逻辑。

这通常是一个 **Domain Service**，因为它需要访问 Repository 来检查唯一性。



```TypeScript
// libs/domain-server/src/modules/auth/services/registration.domain-service.ts

export class RegistrationDomainService {
  constructor(private identityRepo: AuthIdentityRepository) {}

  async registerNewIdentity(email: string, password: string): Promise<AuthIdentity> {
    // 1. 使用 Repository 接口查询 (非纯函数逻辑)
    const isExist = await this.identityRepo.existsByEmail(email);
    if (isExist) {
      throw new Error('Email already registered');
    }

    // 2. 创建聚合根 (纯内存操作)
    const identity = AuthIdentity.create(email, password);

    // 3. 返回新对象 (并没有在这里落库，或者是调用 repo.save)
    return identity;
  }
}
```

### 总结

1. **领域服务不是纯函数**：因为它们通常需要通过 Repository 接口读取数据（IO）或改变系统状态（Side Effects）。
2. **纯函数去哪了？**：请尽量把纯逻辑塞进 **Value Object**（比如 `HashedPassword.create(raw)`）或者 **Entity** 的内部方法里。
3. **持久化在哪里？**：
	
	- **Interface** 在 Domain 层。
	- **Implementation** 在 Infrastructure 层。
	- Domain Service 只调用 Interface。
