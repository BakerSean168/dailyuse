## 统一规范要点

### 📋 标准注释结构

所有模块的 index.ts 文件都遵循统一的注释结构：

```typescript
/**
 * {Module} Module - Domain Server
 * {模块名}模块 - 领域服务端
 * 
 * 【模块职责】
 * 管理...的核心业务逻辑，包括...
 * 
 * 【包含内容】
 * - 聚合根（Aggregates）：列出主要聚合根
 * - 实体（Entities）：列出关键实体
 * - 值对象（Value Objects）：列出核心值对象
 * - 仓储接口（Repositories）：列出仓储接口
 * - 领域服务（Domain Services）：列出领域服务
 * - [其他特殊组件]：如领域事件、错误类、计算器等
 * 
 * 【业务特性】（如果有）
 * - ✅ 特性1：说明
 * - ✅ 特性2：说明
 * 
 * 【依赖规则】
 * ✅ 允许依赖：
 * - @dailyuse/utils（基类：AggregateRoot, Entity）
 * - @dailyuse/contracts（DTO 接口、事件 Map）
 * - @dailyuse/domain-shared（值对象、枚举）
 * 
 * ❌ 禁止依赖：
 * - @dailyuse/domain-client（客户端领域模型）
 * - @dailyuse/infrastructure-*（基础设施层）
 * - @dailyuse/application-*（应用层）
 * - 外部 I/O 库（fs, axios, prisma, ioredis 等）
 */
```

### 🎯 核心改进点

1. **模块职责明确**：
   - 清晰说明模块管理什么业务
   - 列出核心功能范围

2. **组件完整列举**：
   - 聚合根、实体、值对象、仓储、服务
   - 特殊组件（事件、错误、计算器等）

3. **业务特性详细**：
   - 使用 ✅ 标识关键业务功能
   - 简洁明了的特性说明

4. **依赖规则统一**：
   - 明确允许的依赖（✅）
   - 明确禁止的依赖（❌）
   - 保证架构清晰度

5. **中英双语**：
   - 标题中英对照
   - 提升国际化团队可读性
